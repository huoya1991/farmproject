## 1. 背景与目标

### 1.1 背景

企业业务流程管理面临以下痛点：

1. **流程变更依赖开发**：每次流程调整（增删审批节点、修改条件分支）都需要开发人员修改代码、重新发布，响应周期长（平均 3-5 天）
2. **缺乏可视化**：业务流程散落在代码和配置文件中，业务人员无法直观理解流程走向，沟通成本高
3. **复用性差**：每个项目重复开发流程功能，缺乏统一的流程引擎支撑多个业务系统

**为什么现在做**：
- 公司已有 5+ 个业务系统需要流程能力（OA、ERP、CRM、设备管理、项目管理）
- 现有各项目自建流程逻辑，维护成本已超过 200 人天/年
- 业务侧频繁提出流程变更需求，开发响应不及时影响业务效率

**不做会怎样**：
- 继续各项目重复造轮子，人力浪费
- 流程变更响应慢，业务满意度下降
- 流程逻辑分散，难以统一监控和优化

### 1.2 目标用户

| 用户角色 | 特征描述 | 核心诉求 | 使用场景 |
|---------|---------|---------|---------|
| **流程管理员** | IT 部门 1-2 人，熟悉业务但不一定懂代码 | 快速配置新流程、调整现有流程，无需开发介入 | 新建审批流程、修改条件分支、部署流程版本 |
| **业务管理员** | 各部门负责人，完全不懂代码 | 可视化理解流程、监控流程执行情况、处理异常 | 查看部门流程运行状态、催办超时任务、导出流程数据 |
| **终端用户** | 全体员工 | 发起流程、处理待办、查看进度 | 提交请假申请、审批采购单、查看报销进度 |
| **系统集成方** | 其他业务系统的开发人员 | 通过 API 集成流程能力，减少重复开发 | 调用 API 发起流程、接收流程事件回调、查询流程状态 |

### 1.3 业务目标与成功指标

| 目标 | 衡量指标 | 目标值 | 监测方式 |
|------|---------|--------|---------|
| 流程配置自助化 | 业务人员自助配置流程占比 | ≥80%（上线 3 个月后） | 流程创建者角色统计 |
| 流程变更响应提速 | 流程变更平均交付周期 | 从 3-5 天降至 2 小时内 | 流程版本发布时间差 |
| 多系统复用 | 接入流程引擎的业务系统数 | ≥5 个（上线 6 个月内） | 系统接入登记 |
| 流程执行效率 | 流程平均处理时长 | 较上线前下降 30% | 流程实例耗时统计 |
| 系统稳定性 | 流程引擎可用性 | ≥99.9% | 监控告警系统 |

## 2. 需求概述

构建一套可视化可配置的流程引擎平台，支持通过拖拽方式设计流程、配置节点属性与条件规则，实现流程的快速搭建与动态调整，为多个业务系统提供统一的流程能力支撑。

## 3. 功能详细设计

### 3.1 可视化流程设计器

**功能描述**：提供基于 Web 的拖拽式流程设计器，支持通过可视化方式搭建流程结构。

**用户故事**：作为流程管理员，我希望通过拖拽节点、连线的方式设计流程，以便快速搭建和调整业务流程，无需编写代码。

**优先级**：P0

**业务规则**：

1. **节点类型**：支持以下标准节点类型
   - 开始节点（start）：流程入口，每个流程有且仅有 1 个
   - 结束节点（end）：流程出口，可有多个（对应不同结束状态）
   - 审批节点（approval）：需要人工处理的节点
   - 服务节点（service）：自动执行的服务任务（调用 API、执行脚本等）
   - 网关节点（gateway）：条件分支判断（排他网关、并行网关）
   - 子流程节点（subprocess）：嵌套调用其他流程
   - 通知节点（notification）：发送消息通知（邮件、短信、钉钉等）

2. **连线规则**：
   - 节点之间通过连线连接，表示流程走向
   - 每个节点至少有 1 条入线和 1 条出线（开始节点除外）
   - 网关节点的出线必须配置条件表达式
   - 不允许出现死循环（系统需检测并提示）

3. **画布操作**：
   - 支持节点拖拽放置、移动、删除
   - 支持连线创建、删除、调整
   - 支持画布缩放（25%-200%）、平移
   - 支持撤销/重做（最多 50 步）
   - 支持小地图导航（流程超过 20 个节点时显示）

4. **自动布局**：
   - 提供"自动布局"功能，一键整理节点排列
   - 布局算法：从左到右或从上到下，避免连线交叉

**交互流程**：

1. 用户进入流程设计器页面
2. 从左侧节点面板拖拽节点到画布
3. 点击节点，右侧属性面板展示配置项
4. 从节点边缘拖出连线到目标节点
5. 点击连线，配置条件表达式（网关出线）
6. 点击"校验"按钮，系统检查流程合法性
7. 校验通过后，点击"保存"按钮保存流程定义
8. 成功：提示"保存成功"，跳转到流程列表
9. 失败：高亮问题节点，显示错误信息

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 流程缺少开始节点 | 校验失败，禁止保存 | "流程必须有且仅有 1 个开始节点" |
| 流程缺少结束节点 | 校验失败，禁止保存 | "流程至少有 1 个结束节点" |
| 存在孤立节点（未连线） | 校验失败，高亮节点 | "节点 [XXX] 未连接，请补充连线" |
| 网关出线无条件 | 校验失败，高亮连线 | "网关 [XXX] 的出线必须配置条件" |
| 检测到死循环 | 校验失败，弹出提示 | "流程存在循环依赖：A→B→C→A，请检查" |
| 浏览器意外关闭 | 自动保存到草稿箱 | 下次进入提示"检测到未完成的流程，是否恢复？" |

### 3.2 节点属性配置

**功能描述**：支持对每个节点进行详细属性配置，包括处理人、表单字段、条件规则、超时设置等。

**用户故事**：作为流程管理员，我希望为每个节点配置处理人、表单字段和业务规则，以便流程按照业务逻辑正确执行。

**优先级**：P0

**业务规则**：

1. **审批节点配置项**：
   - **节点名称**：必填，如"主管审批"
   - **处理人策略**（必选其一）：
     - 指定人员：从组织架构选择具体人员
     - 指定角色：如"部门经理"、"HR"
     - 发起人上级：自动获取发起人的直属上级
     - 表单字段：从流程变量中读取（如 `#{approver}`）
     - 外部接口：调用业务系统 API 获取处理人
   - **审批方式**：
     - 单人审批：任一人处理即可
     - 会签：所有人审批通过才算通过
     - 或签：超过 N 人通过即算通过（可配置 N）
   - **超时设置**：
     - 超时时间：如"24 小时"
     - 超时动作：自动通过 / 自动驳回 / 转交上级 / 发送提醒
   - **表单权限**：
     - 对每个流程变量设置"可见/可编辑/只读/隐藏"
   - **操作按钮**：
     - 自定义审批按钮（如"同意"、"驳回"、"转办"）
     - 配置按钮颜色、图标、动作

2. **网关节点配置项**：
   - **网关类型**：
     - 排他网关（XOR）：只走满足条件的一条分支
     - 并行网关（AND）：同时走所有分支
   - **条件表达式**：
     - 支持 SpEL 表达式（如 `#days > 3`）
     - 支持可视化条件编辑器（字段 + 运算符 + 值）
     - 默认分支：所有条件都不满足时走的分支

3. **服务节点配置项**：
   - **服务类型**：
     - HTTP 请求：配置 URL、Method、Headers、Body
     - 消息队列：配置 Topic、消息内容
     - 脚本执行：Groovy/JavaScript 脚本
     - 邮件发送：配置收件人、模板
   - **输入参数**：从流程变量映射
   - **输出参数**：执行结果写入流程变量
   - **失败处理**：重试次数、失败后动作（终止/跳过/人工处理）

4. **通知节点配置项**：
   - **通知渠道**：邮件 / 短信 / 钉钉 / 企业微信
   - **接收人**：指定人员 / 流程变量 / 处理人
   - **模板内容**：支持变量插值（如"您有一个待办：${businessKey}"）

**交互流程**：

1. 用户在画布上点击某个节点
2. 右侧属性面板展开，显示该节点的配置项
3. 用户填写/选择各项配置
4. 条件表达式支持"可视化编辑"和"表达式编辑"两种模式切换
5. 点击"保存"按钮，配置生效
6. 成功：属性面板显示"已保存"，画布节点显示配置摘要（如处理人）
7. 失败：高亮错误字段，显示校验错误

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 处理人策略选择"指定人员"但未选择 | 校验失败，禁止保存 | "请选择处理人" |
| 条件表达式语法错误 | 实时校验，高亮错误位置 | "表达式语法错误：第 3 行缺少右括号" |
| 外部接口调用失败 | 测试连接，显示错误 | "接口调用失败：连接超时，请检查网络" |
| 表单字段权限冲突 | 校验失败 | "字段 [amount] 在节点 A 设置为只读，但在节点 B 设置为可编辑，请统一" |

### 3.3 流程模板管理

**功能描述**：管理已设计的流程模板，支持版本控制、发布、停用、权限分配。

**用户故事**：作为流程管理员，我希望管理流程模板的版本和状态，以便控制流程的发布和下线。

**优先级**：P0

**业务规则**：

1. **版本管理**：
   - 每个流程模板有独立的版本号（如 v1、v2、v3）
   - 发布新版本时，旧版本自动归档（不可修改，但可查看）
   - 运行中的实例继续使用旧版本，新实例使用新版本
   - 支持版本对比：高亮显示两个版本之间的差异（新增/删除/修改的节点）

2. **状态流转**：
   - 草稿（draft）→ 已发布（published）→ 已停用（disabled）
   - 草稿状态：可编辑、可删除
   - 已发布状态：不可编辑，只能"发布新版本"或"停用"
   - 已停用状态：不可发起新实例，运行中的实例继续执行

3. **权限控制**：
   - 模板管理员：可编辑、发布、停用、删除
   - 模板使用者：只能查看、发起实例
   - 支持按部门/角色分配权限

4. **模板分类**：
   - 支持多级分类（如"人事类/请假"、"财务类/报销"）
   - 支持标签（如"高频"、"跨部门"）

**交互流程**：

1. 用户进入"模板管理"页面
2. 查看模板列表（支持搜索、筛选、排序）
3. 点击"新建模板"进入设计器
4. 点击某个模板的"编辑"进入设计器（仅草稿状态）
5. 点击"发布"按钮，弹出确认框
6. 确认后，模板状态变为"已发布"
7. 成功：提示"发布成功"，列表刷新
8. 失败：提示错误原因（如"流程校验失败"）

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 发布时流程校验失败 | 阻止发布，跳转到设计器 | "流程校验失败，请修复以下问题：..." |
| 删除已发布模板 | 阻止删除 | "已发布的模板不可删除，请先停用" |
| 停用模板时有运行中实例 | 弹出提示 | "该模板有 12 个运行中实例，停用后不影响这些实例继续执行，确认停用？" |

### 3.4 流程实例监控

**功能描述**：实时监控流程实例的运行状态，支持查看详情、干预异常实例。

**用户故事**：作为业务管理员，我希望监控流程执行情况，以便及时发现和处理异常。

**优先级**：P1

**业务规则**：

1. **实例状态**：
   - 运行中（RUNNING）：流程正在执行
   - 已完成（COMPLETED）：流程正常结束
   - 已终止（TERMINATED）：流程被人工终止或超时终止
   - 已挂起（SUSPENDED）：流程暂停执行（可恢复）

2. **监控维度**：
   - 按模板：各模板的实例数、完成率、平均耗时
   - 按部门：各部门的发起量、处理效率
   - 按时间：日/周/月趋势图

3. **干预操作**：
   - 催办：向当前处理人发送提醒
   - 转办：将任务转给其他人
   - 终止：强制结束流程实例
   - 挂起/恢复：暂停和恢复流程执行
   - 跳转：将流程跳转到指定节点（需权限）

4. **超时预警**：
   - 支持配置预警阈值（如"超过 24 小时未处理"）
   - 预警方式：页面提醒、邮件、钉钉

**交互流程**：

1. 用户进入"实例监控"页面
2. 查看实例列表（支持筛选：模板、状态、时间范围、发起人）
3. 点击某个实例，查看详细信息
4. 详情页展示：基本信息、流程变量、流转轨迹（高亮当前节点）
5. 点击"催办"按钮，向处理人发送提醒
6. 成功：提示"催办成功"
7. 失败：提示"催办失败：处理人已离职"

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 终止实例时有子流程 | 弹出确认 | "该实例包含 3 个子流程，终止后将一并终止，确认？" |
| 跳转到不存在的节点 | 阻止操作 | "目标节点已被删除，请选择其他节点" |

### 3.5 任务管理

**功能描述**：管理用户的待办和已办任务，支持审批、转办、加签等操作。

**用户故事**：作为终端用户，我希望集中处理所有待办任务，以便高效完成审批工作。

**优先级**：P0

**业务规则**：

1. **任务状态**：
   - 待处理（PENDING）：等待处理
   - 已完成（COMPLETED）：已审批
   - 已转办（DELEGATED）：已转给他人
   - 已取消（CANCELLED）：流程被终止

2. **审批操作**：
   - 通过：流程继续向下执行
   - 驳回：流程回退到指定节点（可配置：回退到上一节点/发起人/指定节点）
   - 转办：将任务转给其他人（需填写转办原因）
   - 加签：临时增加审批人（前加签/后加签）
   - 退回：将流程退回到发起人

3. **任务提醒**：
   - 新待办：页面提醒、邮件、钉钉
   - 超时提醒：超过配置时间未处理
   - 催办提醒：被他人催办

4. **批量操作**：
   - 批量审批：选择多个任务，一次性通过（需所有任务在同一模板）
   - 批量转办：选择多个任务，转给同一人

**交互流程**：

1. 用户进入"任务管理"页面
2. 查看"我的待办"列表
3. 点击某个任务，进入审批页面
4. 查看流程详情、审批历史
5. 填写审批意见，点击"通过"按钮
6. 成功：提示"审批成功"，任务从待办列表移除
7. 失败：提示"审批失败：流程已被终止"

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 审批时流程已被终止 | 阻止审批，刷新页面 | "该流程已被终止，无法审批" |
| 转办给已离职员工 | 阻止转办 | "目标用户已离职，请选择其他人员" |

### 3.6 操作日志

**功能描述**：记录流程的所有操作日志，支持查询和导出。

**用户故事**：作为业务管理员，我希望查看流程操作记录，以便追溯问题和审计。

**优先级**：P1

**业务规则**：

1. **日志类型**：
   - 流程操作：发起、审批、驳回、转办、终止
   - 系统操作：超时处理、自动执行
   - 管理操作：模板发布、停用、权限变更

2. **日志内容**：
   - 操作时间、操作人、操作类型
   - 流程模板、业务编号、当前节点
   - 操作详情（如审批意见、驳回原因）

3. **查询条件**：
   - 时间范围、操作类型、操作人
   - 流程模板、业务编号
   - 关键词搜索

4. **导出功能**：
   - 支持导出为 Excel
   - 单次最多导出 10000 条

**交互流程**：

1. 用户进入"操作日志"页面
2. 设置查询条件，点击"查询"
3. 查看日志列表
4. 点击"导出"按钮，下载 Excel 文件
5. 成功：浏览器下载文件
6. 失败：提示"导出失败：数据量过大，请缩小查询范围"

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 导出数据量超过 10000 条 | 阻止导出 | "数据量过大，请缩小时间范围或增加筛选条件" |

### 3.7 开放 API

**功能描述**：提供 RESTful API，供业务系统集成流程能力。

**用户故事**：作为系统集成方，我希望通过 API 发起流程、查询状态，以便将流程能力集成到我的系统中。

**优先级**：P1

**业务规则**：

1. **API 分类**：
   - 流程模板：查询模板列表、获取模板详情
   - 流程实例：发起实例、查询实例状态、终止实例
   - 任务管理：查询待办、审批、转办
   - 数据查询：查询流程变量、操作日志

2. **认证方式**：
   - API Key：简单场景，适合内部系统
   - OAuth 2.0：复杂场景，适合第三方系统

3. **限流策略**：
   - 每个应用每分钟最多 1000 次调用
   - 超过限制返回 429 状态码

4. **回调机制**：
   - 支持配置回调 URL，流程状态变更时主动通知
   - 回调失败时重试 3 次（间隔 1s、5s、30s）

**交互流程**：

1. 开发者在"应用管理"页面创建应用
2. 获取 API Key 和 Secret
3. 阅读 API 文档，调用接口
4. 发起流程实例：POST /api/instances
5. 查询实例状态：GET /api/instances/{id}
6. 审批任务：POST /api/tasks/{id}/approve

**异常处理**：

| 异常场景 | 处理方式 | 用户提示 |
|---------|---------|---------|
| API Key 无效 | 返回 401 | "认证失败：API Key 无效" |
| 参数缺失 | 返回 400 | "参数错误：缺少必填字段 [templateKey]" |
| 限流触发 | 返回 429 | "调用频率超限，请稍后重试" |

## 6. 验收标准

| 编号 | 场景 | Given（前提） | When（操作） | Then（预期结果） |
|------|------|-------------|-------------|-----------------|
| AC-01 | 拖拽创建流程 | 用户已登录，进入流程设计器 | 从左侧面板拖拽"审批节点"到画布 | 画布上出现审批节点，右侧属性面板展开 |
| AC-02 | 连线创建 | 画布上有 2 个节点 | 从节点 A 边缘拖出连线到节点 B | 节点 A 和 B 之间出现连线 |
| AC-03 | 流程校验 | 流程缺少开始节点 | 点击"校验"按钮 | 提示"流程必须有且仅有 1 个开始节点" |
| AC-04 | 配置处理人 | 选中审批节点 | 在属性面板选择"指定角色"→"部门经理" | 节点显示处理人标签"部门经理" |
| AC-05 | 发布流程 | 流程校验通过 | 点击"发布"按钮 | 模板状态变为"已发布"，版本号+1 |
| AC-06 | 发起实例 | 模板已发布 | 调用 API 或点击"发起"按钮 | 实例状态为"运行中"，第一个任务分配给配置的处理人 |
| AC-07 | 审批通过 | 有待办任务 | 填写意见，点击"通过" | 任务状态变为"已完成"，流程流转到下一节点 |
| AC-08 | 超时自动处理 | 审批节点配置"超时 24 小时自动通过" | 任务超过 24 小时未处理 | 系统自动审批通过，记录日志"系统自动通过" |
| AC-09 | 版本对比 | 模板有 v1 和 v2 两个版本 | 点击"版本对比" | 高亮显示新增、删除、修改的节点 |
| AC-10 | API 发起流程 | 已获取 API Key | 调用 POST /api/instances | 返回 instanceId，实例状态为"运行中" |

## 附录

### A. 竞品参考

- **Activiti Modeler**：开源流程引擎，提供可视化设计器，但界面老旧
- **Camunda Modeler**：功能强大，但学习成本高，适合技术人员
- **钉钉宜搭**：低代码平台，流程配置简单，但定制性差
- **泛微 OA**：企业级 OA，流程功能完善，但价格昂贵

- 前端：Vue 3 + bpmn.js（流程设计器）
- 后端：Spring Boot + Flowable/Activiti
- 数据库：MySQL 8.0+
- 缓存：Redis
- 消息队列：RabbitMQ/Kafka（可选）
