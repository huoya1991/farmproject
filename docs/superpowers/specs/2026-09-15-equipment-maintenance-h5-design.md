## 1. 背景与目标

老乡农场小程序新增「设备保养」模块，与「农事生产」「农资进销存」同级，包含保养计划、点检记录、维修记录、设备配件四个功能，以 H5 页面集成。一期先设计并原型化「保养计划」：由设备负责人在移动端录入各自设备的保养计划。

## 2. 范围

本期包含：

- 首页入口：复刻小程序首页风格，新增「设备保养」分区（4 个功能图标）；保养计划可用，点检记录/维修记录/设备配件点击提示「功能建设中」。
- 保养计划闭环：列表（搜索/筛选/逾期标识）→ 新增/编辑表单 → 详情（标记完成/编辑）。
- 设备台账：不建 UI，仅提供 mock 台账数据作为联动查询数据源（字段对齐需求单「设备管理」：设备名称、设备编号、型号规格、设备用途、设备负责人、设备照片）。

本期不包含：点检记录、维修记录、设备配件的页面；设备管理台账 UI；后台字典配置界面；真实后端接口对接；计划删除功能。

## 4. 页面设计

- 统计卡（田块总数量/当前种植面积/种植作物）白色浮层叠在横幅下缘，分区顺序：农事生产、农资进销存、**设备保养（新增）**、任务管理。
- 「设备保养」分区 4 图标：保养计划（可进入）、点检记录/维修记录/设备配件（toast「功能建设中」）。

### 4.2 保养计划列表 #/plan/list

- 顶部田园 hero 横幅（迭代 3，替代原纯色顶栏）：横幅内第一行为返回钮 + 标题「保养计划」+ 右侧绿色「新增」胶囊按钮（进入表单，替代原右下悬浮按钮）；其下品牌区（绿叶 logo + 老乡农场 + 标语「设备保养 · 让农机更高效」），右侧大型拖拉机 SVG 插画；背景为山丘农舍 SVG 场景。
- 白色圆角 sheet（上圆角 18px）上移 22px 叠在横幅下缘，承载搜索/筛选/列表。
- 搜索框：按设备名称/设备编号模糊过滤（实时）。
- 筛选行（迭代 3，替代原状态 tab）：三枚下拉 chip「设备类型 / 保养完成情况 / 负责人」+ 右侧「筛选」重置钮；chip 点击展开下拉面板（单面板复用，同时只开一个），选项带当前选中对勾；选中后 chip 显示所选值并变绿；「筛选」钮一键清空全部筛选与关键词；点击面板外区域收起。设备类型/负责人选项由设备台账动态去重生成。
- 设备卡片：左侧 64px 圆角插画位（按设备类型渲染内联 SVG 农机插画 `DEV_SVG`：拖拉机/收割机/旋耕机/水泵/撒肥机/无人机）+ 中部设备名称（单行省略）/编号 chip/共 N 项 + 型号规格/设备用途/负责人三行 + 右侧状态标签列与「›」；底部三列统计：保养周期（最早下次项的周期）/ 上次保养（本记录本次保养时间）/ 下次保养（最早下次时间，逾期标红）。
- 逾期规则：未完成 且 任一保养项的下次保养时间 < 今天 → 红色「已逾期」标签，且卡片最早下次时间标红。
- 排序：未完成在前、按保养项中最早下次保养时间升序；已完成在后、按本次保养时间降序。
- 列表底部「共 N 条记录」；空态显示 🌱 幼芽插画 + 引导文案（点击右上角「新增」录入第一条计划）。
- 点击卡片进入详情。

### 4.3 保养计划表单（新增/编辑）#/plan/form

分组卡片 + 底部固定保存按钮。全部字段必填。

**保养项绑定结构（迭代 2 核心变更）**：保养周期、保养内容、下次保养时间三者绑定为一个「保养项」，同一设备可录入多个保养项（每项保养内容对应各自的周期与下次时间）。计划级保留：设备信息（4 项）+ 本次保养时间 + 责任人 + 完成情况。

| 字段 | 控件 | 规则 |
|---|---|---|
| 设备名称 | 输入框 + 联动下拉 | 输入即按名称模糊匹配台账；选中候选自动带出编号/型号规格/设备用途/责任人；允许手动输入 |
| 设备编号 | 输入框 + 联动下拉 | 按编号模糊匹配台账，与名称双向联动 |
| 型号规格 | 输入框 | 台账选中后带出，可改 |
| 设备用途 | 输入框 | 台账选中后带出，可改 |
| 本次保养时间 | 日期 | yyyy-MM-dd（原生 date 控件），计划级 |
| 保养项 ×N | 动态卡片列表 | 每项含：保养内容（多行文本，非空）、保养周期（数字 ≥1 整数 + 单位字典）、下次保养时间（日期）；「＋ 添加保养项」追加，仅剩 1 项时不可删除；**每项的下次保养时间必须晚于计划级本次保养时间** |
| 责任人 | 输入框 | 默认当前登录设备负责人；台账选中后若未手动改过则带出台账设备负责人 |
| 完成情况 | 分段选择 | 未完成（默认）/ 已完成 |

联动查询交互：

- 在「设备名称」或「设备编号」任一项输入 ≥1 个字符即触发台账查询（名称 OR 编号模糊），下拉最多 8 条候选，每条显示：名称 + 编号 + 型号规格。
- 点击候选：回填设备名称/设备编号/型号规格/设备用途，并按上述责任人规则带出；下拉收起；表单顶部出现提示条「上次保养时间：YYYY-MM-DD（自动读取该设备最近一条记录）」；该设备无历史记录时提示「该设备首次保养」。
- 点击下拉外区域或清空输入收起下拉；手动输入不匹配台账时不阻断保存（必填校验仍生效）。
- 上次保养时间不落库、不可编辑，纯派生展示（见 5.3）。

校验（保存时）：

- 逐字段校验，未填/不合法 → toast 提示（保养项错误带「第 N 项」前缀）+ 该字段/保养项卡片红框 + 滚动定位到首个错误。
- 每项保养周期值必须 ≥1 整数；每项保养内容非空；每项下次保养时间必须晚于本次保养时间。
- 全部通过 → 写入存储、toast「保存成功」、返回列表并刷新。

### 4.4 保养计划详情 #/plan/detail

- 顶部 hero 卡（迭代 3）：设备 SVG 插画 + 设备名称/编号 chip + 型号规格 + 用途·责任人，右侧状态标签（未完成/已完成 + 逾期标签，规则同列表）。
- 只读展示全部字段；保养项按编号卡片展示（内容 + 周期 chip + 下次保养时间，未完成逾期的项标红）；展示派生的「上次保养时间」（无历史记录显示「—」）。
- 操作：未完成时显示「标记完成」+「编辑」；已完成时仅「编辑」。标记完成需二次确认，完成后状态变为已完成。
- 本期不提供删除。

## 5. 数据模型与后台配置

### 5.1 字典配置（后台数据库可配置）

- 字典类型 `maint_cycle_unit`（保养周期单位），初始值：小时、天、公里。
- 原型：JS 常量 `SYS_DICT` 模拟，页面单位下拉从该常量渲染（验证「后台可配置」语义：改配置即改选项）。
- 生产：对应后台字典表（如 sys_dict，dict_type='maint_cycle_unit'），接口 `GET /api/dict/{type}`。

### 5.2 设备台账（mock，联动查询数据源）

字段：id、name（设备名称）、code（设备编号）、model（型号规格）、usage（设备用途）、owner（设备负责人）、photo（设备照片，原型占位）、**type（设备类型，迭代 3 新增，列表筛选项）**、**svg（插画键，迭代 3 新增，映射内联 SVG 农机插画）**。预置 6 条：拖拉机 TR001（约翰迪尔 6B-1204，耕地作业，张三）、联合收割机 LHS002（沃得 4LZ-5.0，粮食收割，李四）、旋耕机 XGJ003（东风 1GQN-200，土地旋耕，王五）、水泵 SB004（新界 80QZ-60，农田灌溉，赵六）、撒肥机 SFJ005（中联 2F-1000，施肥作业，陈七）、植保无人机 UAV006（大疆 T40，植保喷洒，王强）。

### 5.3 保养计划记录（迭代 2 结构：保养项数组）

```
plan = {
  id, deviceId(可空，手动录入时为 null),
  deviceName, deviceCode, modelSpec, usage,
  items: [                    // 保养项数组，至少 1 条
    {
      content,                // 保养内容（非空）
      cycleValue, cycleUnit,  // 保养周期（≥1 整数）+ 单位（字典）
      nextDate                // 该项下次保养时间 yyyy-MM-dd
    },
    ...
  ],
  thisDate,                   // 本次保养时间 yyyy-MM-dd（计划级）
  owner,                      // 责任人
  status: 'undone' | 'done',  // 完成情况
  createdAt, updatedAt
}
```

- 派生规则：
  - `planNextDate(plan) = min(items[].nextDate)`（最早下次保养时间，用于列表展示与未完成排序）。
  - 逾期：`status === 'undone' && items.some(i => i.nextDate < today)`；列表/详情对逾期项标红。
  - 上次保养时间（不存储）：与当前记录 `deviceCode` 相等（编号字符串相等，手动录入记录同样按编号匹配）的其他记录（排除自身）中 `thisDate` 的最大值；表单页用于选中设备后的提示条，详情页用于展示。
- 原型持久化：localStorage（key：`lx_maint_plans_v3`，迭代 3 切换命名空间以隔离旧格式数据），预置 6 条示例数据（每台设备 1 条；含 1 条逾期的植保无人机记录、3 项保养项的拖拉机样例、2 条已完成样例；日期以 2026 年为基准保持相对间隔）。
- 当前登录用户 mock：王强（设备负责人），用于责任人默认值。

### 5.4 生产接口约定（预留，本期不实现）

- `GET /api/dict/{type}` 字典；`GET /api/device?keyword=` 台账联动查询
- `GET /api/maint-plan?keyword=&status=` 列表（响应含 `planNextDate`）；`GET /api/maint-plan/{id}` 详情（响应含 `items[]` 与 `lastDate`）
- `POST /api/maint-plan` 新增（请求体含 `items[]`）；`PUT /api/maint-plan/{id}` 编辑；`PUT /api/maint-plan/{id}/status` 标记完成
- 小程序跳转 web-view 时带登录 ticket，H5 换 token；录入/编辑权限限设备负责人。

## 7. 验收要点（浏览器实测，迭代 3 已全过）

1. 首页田园横幅（品牌/天气/拖拉机插画）+「设备保养」分区 4 图标；保养计划与 tabbar「设备」均可进入列表，其余 toast「功能建设中」。
